## 0. Design principles that cut across every section

1. **One source per dedup_key in P2.1.** No two P2.1 sources emit the same dedup_key. D-036 lets only the stored owner
   (or a strictly higher-ranked affiliation) change facts; every P2.1 source is `official-nonpartisan`, so a shared key
   would freeze the facts of whichever arrived first (e.g. a floor result line would stop `house.clerk.votes` from ever
   adding counts and member votes). Cross-source links are `related[]` entries only. (Decision row R-11.) This
   SUPERSEDES the EVENT_MODEL merge-rule sentence that has press-gallery text merge into the vote event ("Free-text
   sources contribute first_seen_at and a corroboration link") and answers D-036's "revisit when two sources share
   dedup_keys" for P2.1: they do not. Known cost, recorded as P2.2 page question Q-P1: each result appears as two rows
   (gallery/floor line + official vote) until the page groups rows by a shared `related` vote key, and the gallery's
   earlier sighting does not improve the vote row's first_seen_at.
2. **Fail closed on structure, label on meaning.** Unknown structure, an unknown value in a closed vocabulary that
   decides `passed`, or a count that does not reproduce its total = health `drift`, nothing from that payload. An
   unknown *question kind* (which only sets tier and title wording) = publish with a neutral title at P3 plus a health
   detail, never P0 by default (R-14). Exception: an unknown question whose text matches
   `/veto|objections of the president/i` = drift ("possible veto vote, question not in the table"), because the P0 class
   must never be silently demoted (critique T5/C4). Question and result strings are compared case-insensitively after
   whitespace collapse (the Clerk printed `Call By States` in 2023 and `Call by States` in 2025: live 2026-10-03
   `evs/2023/roll001.xml`).
3. **Never guess a time.** Naive Eastern wall times go through one helper (§1.6). A wall time that does not exist (spring
   forward) = drift for official XML sources; an ambiguous one (fall back) = that time field `null` plus
   `result.time_note`; human-written text (press gallery) = `null` in both cases.
4. **Titles are ours; source words are `official_text`** (D-043). Titles may carry identifiers we format ourselves (bill
   and PN numbers, roll numbers, tallies), never a bill title, vote question, vote_title, matter text or gallery prose.
5. **Pure adapters, head-only parsing.** No network, no clock (the clock is `res.fetchedAt`). Bulky parts (member lists,
   older floor actions, post HTML) are cut by string scanning before any XML/HTML parsing (the `lib/rss.ts` pattern).

### 1.1 What "v0.2" is

v0.2 is additive and documentation-led. **No new event_type, status, branch or body value is needed**: the v0.1 enum
already lists `floor.convened|adjourned|recess|pro_forma|action|speaking`, `vote.opened|result`, `hearing.scheduled`,

  folded into `event.schema.json` at P2.2 go-live;
- a second record type, the member-vote side record (§2), with its own schema file (same subpath);

const to `"0.2"` (accepting both). Reason: `finalizeEvent` stamps every event, so a bump now would change every event

`fr.api` and `wh.feeds` goldens must stay byte-identical: that is the test that the change is additive.

### 1.6 Eastern wall time -> UTC (one helper, `packages/adapters/src/lib/eastern.ts`)

```ts
export type EtResult = { ok: true; utc: string } | { ok: false; reason: 'invalid' | 'nonexistent' | 'ambiguous' }
/** Naive America/New_York wall time -> UTC "…Z". Tries both offsets (-04:00, -05:00); keeps those whose UTC instant
 * formats back (Intl, timeZone America/New_York, h23) to the same wall time. 0 matches = nonexistent (spring-forward
 * gap), 2 = ambiguous (fall-back hour), 1 = ok. Every part is range-checked first (no Date roll-over). */
export function easternToUtc(y: number, mo: number, d: number, h: number, mi: number, s?: number): EtResult
```

Required tests: 2026-09-16 19:05 -> 23:05Z; 2026-01-08 15:23 -> 20:23Z; 2025-05-22 00:29 -> 04:29Z; 2026-11-01 01:30 ->
ambiguous; 2026-03-08 02:30 and 2027-03-14 02:30 -> nonexistent; 2026-11-09 15:00 -> 20:00Z and 2026-10-05 16:00 ->
20:00Z (same UTC across the fall-back, the senate.schedule DST trap); 2026-11-02 16:30 -> 21:30Z; 2026-02-30 -> invalid.
Never `Date.parse` a naive string (Node reads it in the machine's zone: senate.schedule and pressgallery scouts).

Each source has its own *text* parser (formats differ and must not share one, house scout): House `D-Mon-YYYY` +
`time-etz HH:MM` cross-checked against the `h:mm AM|PM` text; Senate `/^([A-Z][a-z]+) (\d{1,2}), (\d{4}),  (\d{2}):(\d{2}) ([AP]M)$/`
(TWO spaces; 12 AM = hour 0, 12 PM = 12); floor `YYYYMMDDTHH:MM[:SS]`; schedule string fields; gallery `h:mm a.m./p.m.`.

### 1.7 Exact schema changes: a separate `@ced/schema/v02` subpath (the Worker's schema stays byte-identical)

**Why a subpath (critique C1/B1, verified):** `.github/workflows/deploy.yml` runs `wrangler deploy` for every
`workers/*/` after CI passes on ANY push to main (no path filter; grant G-007). The Worker imports `eventJsonSchema`,
`validateEvent` and friends from `@ced/schema` (`workers/api/src/fastpath.ts` line 13, `hub.ts` line 25), and
`fastpath.ts` line 133 hashes `JSON.stringify(eventJsonSchema)` into the D-050 fingerprint. Editing
`event.schema.json`, `validate.ts` or `index.ts` would therefore ship a new validator to ced-api on the first push after
p2.1 merges (a live change D-058 forbids) and clear every D-050 mark during the Phase 1 latency window. So in P2.1:

  `id.ts`, `order.ts`, `api.ts`. `types.ts` gets no change either (the stale header comment that cites a nonexistent
  `tests/types.test.ts` is reported to the main session, not edited here).
- **New, imported only by tests and `@ced/adapters/fixture-only`:** `packages/schema/src/v02/` with
  `vote_result.schema.json`, `member_votes.schema.json`, `types.ts`, `validate.ts`, `index.ts`;
  `packages/schema/package.json` `exports` gains `"./v02": "./src/v02/index.ts"`.
- **P2.2 (go-live, one decision row):** fold `voteResult` and the conditional below into `event.schema.json`, bump the

## 2. Member-vote side records

### 2.1 Shape (`packages/schema/src/v02/member_votes.schema.json` + `v02/types.ts`, §1.7)

One record per roll call, never a feed event. Built by the vote adapter from the same response as the `vote.result`
event, returned in `AdapterOutput.records` (§3.0), validated with `validateMemberVotes` and paired with its event by
`checkVotePair` in tests (§1.7). The record is standalone (served alone by the deferred API, §5), so it carries its own
identity fields; `validateMemberVotes` checks that they agree with `ref` and `vote_key`.

```ts
export interface MemberVotesRecord {
  record_type: 'member_votes'
  record_version: '0.1'
  ref: string              // = the event's member_votes_ref, "votes/senate/119/2/256.json"
  vote_key: string         // = the event's object_key, "vote:senate:119:2:256"

  counts: { yea: number | null; nay: number | null; present: number; not_voting: number; candidates?: Array<{ name: string; votes: number }> }

export interface MemberPosition {
  member_key: string       // "bioguide:A000370" | "lis:S293" (Senate id not in the map)
  id_confidence: 'authority' | 'mapped' | 'unresolved' // House name-id = authority; Senate LIS mapped via map = mapped

  name: string             // map displayName when found, else the source's own text (never invented)
  name_source: 'map' | 'source'
  source_name: string      // verbatim: House <legislator> text ("Hernández"), Senate member_full ("Graham (R-SC)")
```

```ts
export interface Target { endpoint: string; url: string }

export interface Endpoint {
  // …existing fields…
  /** Dynamic endpoint: its URLs come from the latest accepted (ok/empty) parse of endpoint `from` (AdapterOutput.targets

  notYetStatus?: number

  targets?: Target[]
```

### 3.5 `senate.pressgallery` (`packages/adapters/src/sources/senate_pressgallery.ts`)

**Scope v1: the Daily Press Gallery only.** The Periodical gallery has no clock times on result lines and is often

**Endpoint:** `daily_posts`
`https://www.dailypress.senate.gov/wp-json/wp/v2/posts?per_page=3&_fields=id,date,date_gmt,modified,modified_gmt,slug,status,type,link,title,content,categories`,
validator body-hash (REST sends no ETag/LM and ignores IMS: `dailypress_posts_newest3_fields_ims_200.json`, scout);
cadence 60 / 300; `calendar: { chamber: 'senate', recess_s: 900 }`; budget 70/h; SLO 120 s. Always send `_fields`
(unfiltered is ~243 KB for 10 posts).

**Parsing:** JSON.parse (~33 KB). Body must be a JSON array (an object such as `{"body":{"code":…}}` = drift:
`dailypress_post_999999999_envelope_NEGATIVE_200_error_body.json`); `[]` on this endpoint = drift (a 1,842-post site
cannot list nothing). Per post: required `id`, `date_gmt` (`^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d$`, append `Z`), `modified_gmt`,
`link` (https on `www.dailypress.senate.gov`), `title.rendered`, `content.rendered`, `status === 'publish'`, `type ===
'post'`, no duplicate id; else drift.

**Session day** (per post): parse `(Weekday,)? Month D(st|nd|rd|th)?,? (YYYY)?` from the decoded title; use the title
date if its weekday matches and it is within -14..+7 days of the post's Eastern day (from date_gmt); else retry with the
post's year; else, if the title weekday is the post's own weekday and the day is off by exactly 1, use the post's day;
else hold the post (zero events from it, named in the health detail; the payload is not drift). Titles that are not a
date (`dailypress_post_56415_announcement_not_floor_log.json`) = not a floor log, skipped with a note. Empty content
(stub `dailypress_posts_165481_scheduled_modified_before_date.json`) = skipped with a note.

**Entries:** split `content.rendered` into `<p>`/`<li>` blocks; decode entities BEFORE matching (`&#8211;`). A block
starting with `/^(\d{1,2}):(\d{2})\s*(?:[-–]\s*\d{1,2}:\d{2}\s*)?([ap])\.m\./i` starts an entry. A block starting
`/^\d{1,2}:\d{2}\s/` with no a.m./p.m. (166593 "5:02 Senator Kelly spoke on AI.", opened) is its OWN entry with
`occurred_at: null`, time part `U{h:mm}` (§1.4), skipped by the midnight-roll walk. Following untimed blocks are an
entry's continuation until the next timed block, a separator, or a block matching `/^(The Senate will|At \d|Following)/`
(critique T9, verified: 166969 has no separator and its schedule blocks 63-65 would otherwise continue the oldest
entry); such a block starts the schedule part. Separators: a block of only `*` (3+) or only
em dashes. The **schedule part** is a part (between separators) whose first non-empty block starts with
`/^(The Senate will|At \d{1,2}:\d{2}|Following)/`; its blocks never become entries in v1. An em-dash line inside the
log is a day break, not a schedule boundary (162959: "The above happened on Friday, June 5th." then an em-dash line,
opened). If both a schedule-looking part and leading-clock blocks occur in the same part, hold the post. Builders must
hand-count and pin the entry count of 167105, 166515, 166855, 166593, 162959 and 167288 (any rule change that alters a
count is a reviewed golden diff).

**Clock -> instant:** walking from the bottom (oldest) up, roll to session day + 1 when the time drops by more than 6 h
(midnight); a smaller drop = an out-of-order typo -> `occurred_at: null` (162959's `10:30 p.m.` between 11:40 and 10:57,
scout). Ranges use their start (taking the end's a.m./p.m. unless that would put the start after the end). Ambiguous
or nonexistent wall time -> null.

**Typing** (critique T3, verified: the earlier unanchored `recess` rule typed 166969's and 166665's "2:15 p.m. The Senate

Gallery log"; titles never quote the gallery and omit the clock:
